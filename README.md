# SmartAM SLM System

Windows 目标电脑推荐双击根目录 **`deploy_windows.bat`**，自动检查并补齐环境、安装依赖、构建页面、配置局域网访问并启动。已有环境和未变化的构建会跳过，不依赖 Codex、VS Code 或固定名称的 Conda 环境。

默认部署仅安装基础运行依赖，不需要 PyTorch、CUDA、显卡或推理环境。五台随附设备直接播放处理好的识别、溯源和红外结果；“真实模型处理”仍可按需启用。

跨平台手动入口为 `python start_platform.py`，首次准备环境见下文“新电脑独立部署”。

根目录仅保留两个 Windows 批处理入口：

- **`deploy_windows.bat`**：首次部署、更新后部署，检查并补齐环境，按变化构建页面并启动。
- **`start_platform.bat`**：日常启动，复用 `.venv` 和已构建页面，不下载、不安装、不重新构建。缺少环境或页面源码变化时提示先运行部署脚本。
- **`start_smartam.bat`**：无浏览器、无交互的日常启动入口，供 Windows 任务计划使用。
- **`enable_autostart.bat`**：注册并立即启动当前用户登录后的 SmartAM 自动启动任务。

Windows 部署和日常启动固定使用 `8001` 端口。本项目已运行时会复用现有服务；若 `8001` 被其他进程占用，启动脚本会停止该端口的占用进程后再启动本项目。

部署完成后，双击 `enable_autostart.bat` 可注册任务 `SmartAM_System_AutoStart`。任务在当前用户登录后延迟 30 秒启动，以便 Windows 网络和用户环境完成初始化；任务使用 `start_smartam.bat`，不会自动打开浏览器。取消自启动可运行：`schtasks /Delete /TN "SmartAM_System_AutoStart" /F`。

## Windows 一键部署（推荐）

适用 Windows 10/11 x64。将本分支完整下载或拉取到目标电脑，在解压后的项目根目录双击 `deploy_windows.bat`，不要在压缩包内直接运行。首次补齐环境和依赖需要联网；已有依赖且未更新时会跳过下载。

| 检查项 | 已满足时 | 缺失或变化时 |
| --- | --- | --- |
| Python | 复用 Python 3.10–3.13 x64 | 通过 WinGet 安装 Python 3.13 |
| 项目环境 | 验证并复用 `.venv` | 创建独立 `.venv`，不向系统 Python 安装项目依赖 |
| VC++ x64 运行库 | 根据安装记录跳过 | 通过 WinGet 安装 |
| Node.js / npm | 复用 20.19+、22.12+ 或 24+ 的兼容版本 | 通过 WinGet 安装 Node.js LTS |
| 后端依赖 | 核对 requirements 的版本约束及 `pip check` | 用 pip 补齐，再验证实际导入 |
| 前端依赖 | 核对锁文件、运行时和完整依赖树 | 使用仓库的 `package-lock.json` 执行 `npm ci` |
| 页面构建 | 输入和产物的 SHA-256 一致则跳过 | 重新构建，同源访问且不启用模拟接口 |
| 防火墙 | 本应用规则符合要求则跳过 | 请求 Windows 管理员确认，只放行专用/域网络、本地子网的实际 TCP 端口 |
| 服务 | 本项目已运行则直接打开页面 | 启动并等待健康检查成功后打开浏览器 |

缺少 WinGet 时，安装 Windows“应用安装程序”，或先手动安装上述运行环境再重运行；不从非官方镜像下载未知安装器。安装命令使用 [Microsoft WinGet 的精确包 ID](https://learn.microsoft.com/windows/package-manager/winget/install)。首次系统组件安装可能出现 Windows 权限确认，请允许后继续。脚本仅为本次 PowerShell 进程设置执行策略，不修改全局执行策略。

服务启动后控制台列出网卡地址，同一局域网访问 `http://<部署电脑IP>:<实际端口>/slm/dashboard`。保持窗口开启，Ctrl+C 停止。工厂可信局域网若被 Windows 标为“公用网络”，需要在 Windows 中改为“专用网络”；脚本不会自动更改网络类别。访问电脑的代理仍需让该 IP 直连。

重复双击时，安装阶段有互斥锁防止同时修改环境；本项目已运行时只打开原页面。若 `8001` 被其他进程占用，脚本会按 PID 停止该进程；必要时请求 Windows 管理员权限，清理失败则明确报错。后端只绑定 `8001`，健康检查、浏览器地址和防火墙均使用该端口。更新仓库后先停止原服务，再双击脚本即可按变化补齐依赖和重建。环境损坏会明确报错，不自动删除 `.venv` 或个人文件。

部署成功状态保存在 `.deployment/`，日志在 `logs/deployment/`（保留最近 5 次）；两者不提交 Git。不要将另一台电脑的 `.venv`、`node_modules` 或 `.deployment` 一起复制过来。安装/构建失败不会写入该步骤的成功状态，解决错误后重复运行即可。

本脚本完成平台软件和仓库随附设备案例的部署。实体相机 SDK、PLC 地址和特定 GPU 驱动仍按目标硬件配置。当前已通过自动化逻辑检查和 PowerShell 解析/分支检查，目标 Windows 的安装与 UAC 流程需实机验收。

## 日常访问与停止

Windows 完成部署后双击 `start_platform.bat`。控制台会显示本机和各网卡的完整地址，例如 `http://192.168.1.20:8001/slm/dashboard`。页面、API、图片和 WebSocket 共用地址栏的主机及端口，无需修改前端配置；HTTPS 使用 WSS。不要把 `0.0.0.0` 当作浏览器访问地址。

保持服务窗口开启，按 Ctrl+C 停止。已删除根目录旧的 `start-dev.bat`、`start_slm_complete.bat` 和 `stop_slm.bat`，避免误用固定端口或结束其他程序的旧脚本。子目录中的安装辅助脚本不属于日常启动入口。

## 仓库随附设备案例

`feature/GJW_Contribution` 包含可直接播放的设备案例。正常 `git clone` / `git pull` 会取得全部分卷，不需要 Git LFS 或开发者电脑上的论文数据目录；可选真实处理用的权重也随仓库分发。首次打开设备时，后端校验 SHA-256 并解包到 `backend/data/replay_runtime/`；该目录是可重建的运行缓存，不提交。

| 设备入口 | 随附完整层数 | 数据内容 |
| --- | ---: | --- |
| BLT-S430 B17 | 402 | 铺粉/熔化图像、扭矩、设备参数、已封存识别与双因素溯源结果 |
| 铂力特 S430 B44 | 26 | 图像、扭矩、设备参数、报警、识别与双因素溯源 |
| 铂力特 S310 B10 | 252 | 图像、扭矩、设备参数、报警、识别与双因素溯源 |
| 铂力特 S310 B15 | 101 | 图像、扭矩、设备参数、报警、识别与双因素溯源 |
| 华科 CRPBFM130 | 815 | M130 牙冠任务的铺粉/熔化可见光与红外图像、独立红外识别与可见光双因素溯源 |

设备群总览和监测页面按采集工作流显示；播放、暂停、倍速和定位层统一在对应设备的系统设置中操作。普通设备的回放设置禁用。每台案例设备使用独立的播放进度、采集通道显示选项与本地调控方案记录。

新打开或刷新页面后，案例从第一层以 1 倍速自动播放；末层结束后自动循环。同一页面会话内切换功能页保留当前进度、倍速和暂停状态。真实模型处理开关仍按设备保存。

系统设置中的“设备数据源”与设备群使用同一列表，区分逐层案例、真实采集和目录视频。案例不依赖 `mock_video`；目录视频仍扫描单台设备目录下 `mock_video/CH1`、`CH2`、`CH3` 内的支持格式视频，点击“刷新列表”重新读取。资源已配置不代表硬件已连接，真实硬件连接状态由采集页确认。

五台设备均提供数据接入、异常识别、异常溯源和闭环调控入口。案例设备不会初始化相机、PLC 或下发控制指令；闭环调控页依据当前层分析并保存独立的参数方案。

发布数据位于 `backend/replay_cases/`，合计约 406 MiB，各分卷小于 40 MiB。完整目录和分卷哈希记录在 `catalog.json`；各包内另有文件校验清单与来源记录。传感器数值、秒级时间及同秒采样顺序保留；图像是最长边 1200 像素的展示版本，原图文件名、尺寸与 SHA-256 记录在 `provenance.json`，不用于重新推理。原始采集缺口按明确分段跳过。

设备卡片照片在 `frontend/public/device-images/`。S310 使用用户提供的同型设备图，S430 使用用户提供的已打码现场图，作为展示替代图，不表示拍摄对象与每台设备编号一一对应。

### 新电脑独立部署

1. 拉取本分支，安装 Python 3.10+、Node.js 18+；Linux 需要系统的 `ip` 命令（iproute2）。
2. 在项目根目录用所选 Python 环境安装后端依赖：`python -m pip install -r backend/requirements.txt`。
3. 运行 `python start_platform.py`。

启动器使用当前 Python 环境，首次安装前端依赖，每次构建正式页面，然后在所有网卡上启动服务，并列出带实际端口的访问地址。端口占用时自动尝试下一端口，不终止占用者。不需要 SSH 转发或修改 `.vscode` 设置；依赖安装完成后，日常启动不需要 Codex。使用 Ctrl+C 停止。

同一局域网的其他电脑打开 `http://<部署电脑IP>:<实际端口>/slm/dashboard`。更换电脑或 IP 后不需要修改源码；页面、API、图片和 WebSocket 使用同一访问地址。多网卡电脑应选访问方可达的地址，Docker/虚拟网卡地址不一定可达。

网络条件：部署电脑的防火墙需允许局域网访问实际 TCP 端口（Windows 脚本自动处理）；访问方的代理需对该 IP 直连。这些是操作系统/网络设置，应用无法替客户端代理配置绕过规则。`Privoxy` 错误应检查访问方代理，不需要修改平台页面。

也可以手动构建和启动：

```bash
python -m pip install -r backend/requirements.txt
npm install --prefix frontend
npm run build --prefix frontend
cd backend
python main.py
```

打开启动窗口显示的地址（默认 `http://localhost:8000/slm/dashboard`），点击设备卡片进入设备监测，或点击“成形监测”进入数据接入。Linux 已配置 `pytorch_env` 环境时也可运行 `./start_slm_complete.sh`。

验证案例完整性及时间对齐：

```bash
cd backend
python -m pytest tests -q
```

重建发布包仅供维护者使用，需要原始封存案例、现场数据集和逐层索引；普通使用者不需要执行。示例：

```bash
python scripts/build_portable_replays.py \
  --raw-root /path/to/7103_factory_dataset_v1 \
  --pre-root /path/to/7103 \
  --current-case /path/to/blt-s430-20240828
```

### 默认结果播放与可选真实处理

系统默认使用处理好的逐层结果。系统设置仅显示“真实模型处理”开关，首次进入为关闭状态；手动选择按设备保存，互不影响。普通设备的历史回放控制禁用。业务页面继续使用统一采集时间，识别、溯源、调控依据随当前层更新。前后跳转不会显示未来层结果，贡献曲线最多显示 50 个已到达层。

关闭开关时直接读 `backend/analysis_packages/<case>/results.json`，不创建推理器、不读取模型权重、不下载在线模型。打开时使用仓库内 `inference_models/` 权重和 `analysis_packages/` 的标准化输入，在 CPU 上实际执行网络及逐输出两区 Shapley，无需 CUDA。输入分卷与结果经过 SHA-256 校验；权重单独校验并使用 `weights_only=True` 加载。B17 默认保留原识别展示；溯源使用修正分区后重新计算的封存结果，真实处理路径采用相同分区与判定逻辑。

直接跳转到后段时只重新处理当前显示窗口，正常参照使用该层封存的前序参照编号，并由当前模型复核其正常性；不会从第一层重跑整个任务。两区 Shapley 采用四种区域组合，BLT 扭矩保持该层实际输入。每个输出的贡献单位为 logit 改变量，双输出概率分别保留；识别总分取两侧概率较大值。新封存结果的归因方向由该侧概率达到 0.5 且至少一区贡献超过校准上限共同决定。概率达到异常阈值但归因未确认时显示“已识别异常，归因待确认”；概率未达到异常阈值但贡献超限时显示“贡献超限，待复核”。二者都未触发才显示“未见异常”，待确认状态不直接生成参数调整指令。工艺侧与设备侧贡献分别对照本侧上限，不能交叉比较两条阈值线。

如果真实处理的依赖、权重或输入不满足条件，当前设备直接切回自己的封存结果，开关同步关闭。原因及异常堆栈仅记录在后端日志，设置页不显示原因或技术说明；README 保留这一约定。封存包损坏会明确报读取错误，不用其他案例替代。基础依赖 `backend/requirements.txt` 不包含 PyTorch/torchvision，Windows 一键脚本也不检查或安装这两项。平台启动、设备清单及默认案例页面不加载模型；缺少推理依赖时，误打开真实处理开关会按上述约定切回该设备的封存结果。首次部署仍需基础 Python、Node.js 和 Web/图像处理依赖，由部署脚本检查补齐；“无需推理环境”不等于没有任何运行依赖。

数据与模型边界：

- BLT 使用 B17 源域训练的图像＋扭矩双输出模型，输入为实际成形区图像与两通道铺粉段扭矩。B44/B10/B15 的新增结果均由各自原始输入实际计算，不复制 B17 标签；尚未针对这三台设备重新标定或验证识别精度，不能将接入成功等同于跨设备性能已验证。
- M130 使用已归档视觉双输出权重，并按训练约定执行粉床背景颜色标准化。案例来自“11月20日-高功率翘曲／牙冠”真实图像序列；没有扭矩和环境采样，因此相关展示通道隐藏。现有 815 层均加入铺粉后与熔化后红外图像，四路图像按各自原始采集时间到达，通道勾选分别控制展示。每个播放分段是铺粉后图像至熔化后图像的时间窗口，不代表完整打印层耗时。设备照片使用提供的 `CRPBFM130.jpg`。
- 红外识别采用本地归档的 `ir_before_seed0` 五分类权重（正常、刮刀条纹型缺粉、铺粉不足型缺粉、翘曲、未熔合），使用训练配置的全图颜色标准化并独立输出类别、置信度和 `1-P(正常)`。该输出已实跑封存，真实处理开关也会重新执行红外模型。权重、训练来源和归一化配置哈希记录在 `backend/inference_models/registry.json`。红外图像未做温度标定，也未与可见光空间配准，因此不生成温度数值、不套用可见光掩膜，不将独立红外结果冒充融合溯源。
- BLT 分区版本 `platform-exclusion-v2` 在原图亮度差分之后、闭运算之前识别外围长直机械条带，排除平台/刮刀条带及 letterbox 灰边。保留内部多个零件和非贯穿画面的靠边零件，避免硬性居中裁剪。Shapley 四种组合中排除域固定为当前图像，不将其变化转移到粉床贡献。四台设备的分区和贡献均已重新封存，原分类输入与概率不变；现有正常验证阈值仍来自源设备，尚未针对新分区和新设备重新标定，图像分区与识别精度仍需设备侧验证。
- 首层或尚无先前正常参照的层只给识别结果；数据到达、形成有效参照后才出现溯源。缺少数据不伪造贡献，也不填充随机小值。
- 模型输出顺序、原始权重来源和哈希在 `inference_models/registry.json`；各案例阈值、输入图像来源、参照及分卷校验在 `analysis_packages/`。展示图像与实际标准化模型输入分别保存。

### 后续采集数据的模型接口

已绑定模型的五台设备可通过 `POST /api/slm/analysis/devices/{deviceId}/layers` 提交新任务的逐层输入；OpenAPI 页面 `/docs` 可查看字段和试调用。这是采集端适配接口，当前页面播放列表仍使用仓库随附案例；新任务进入设备时间轴需要由采集端接入任务发布流程，接口不会将新任务悄悄混进旧案例。

使用 multipart：`before` 为铺粉后图像；BLT 同时提供 `after` 熔化后图像，M130 提供同尺寸 `mask`（非零为零件区）。M130 可额外上传 `infrared_before` 铺粉后红外图像，按独立红外模型真实处理并随该层结果存储；该图像通过结果内的 `image.url`（`?kind=infrared`）读取。`metadata` 为 JSON 字符串：

```json
{
  "task_id": "new-build-001", "task_name": "新成形任务",
  "layer": 1, "total_layers": 1000, "time": "2026-10-21T12:00:00+08:00",
  "roi": [260, 160, 2344, 1488],
  "torque_time": [0, 1, 2], "scraper": [2.1, 2.3, 2.2], "platform": [-12.1, -12.2, -12.0]
}
```

上述扭矩数值仅说明请求结构，不是随附案例数据。BLT 应传完整铺粉段的实际采样，时间严格递增，两通道等长，ROI 必须在原图内；M130 不传 ROI/扭矩字段。设备型号、输入模态、ROI 与训练预处理必须匹配，不承诺任意格式、任意模态的数据都适用。模型为 CPU 执行，不触发硬件指令。

新任务按设备和任务 ID 隔离保存至 `backend/data/live_analysis/`（忽略 Git），真实处理后保留标准化输入、输出、输入及模型哈希。`GET /api/slm/analysis/devices/{deviceId}/tasks/{taskId}/layers/{layer}` 直接读取已保存结果，不调用模型。相同输入重复提交返回已有结果，同层不同输入拒绝覆盖；层号与采集时间须递增。正常参照只从该任务已处理的较早层选择。新任务没有自己的封存结果时，推理失败返回 503，不能借用旧案例播放结果。

## 按需启用真实推理

默认播放无需执行本节。Windows 完成基础部署后，在项目根目录运行：

```bat
.venv\Scripts\python.exe -m pip install -r backend/requirements-inference.txt
```

该清单使用 PyTorch 官方 CPU 软件源，不安装 CUDA。安装成功后重启平台，再从对应设备的系统设置启用“真实模型处理”。Linux 使用所选 Python 环境运行同一条 `python -m pip install -r backend/requirements-inference.txt` 命令。已有推理环境可继续使用，基础部署不会卸载其推理依赖。新采集任务必须具备相应模型输入和可用推理依赖；没有自己的封存结果时返回明确的处理失败，不使用旧案例替代。

基础部署验收：在只安装 `backend/requirements.txt` 的环境中，额外安装测试工具 `httpx`，运行 `python -m unittest discover -s backend/tests -p test_playback_deployment.py`。该检查覆盖完整应用路由、五台设备的封存快照与图像、红外结果、调控配置，以及禁用推理依赖时误开真实处理的行为。
